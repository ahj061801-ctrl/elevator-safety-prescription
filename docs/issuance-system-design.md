# 승강기 안전처방전 자동 보관·발급대장 구축 명세

## 확정 운영 조건
- 사용자 범위: 한 지사 소속 복수 검사원과 지사 관리자
- PDF 접근: 인증된 활성 사용자이며 해당 지사에 소속된 경우에만 허용
- 기존 GitHub Pages 작성 화면은 유지하되, 발급 완료 및 보관 처리는 백엔드에서 수행
- PDF는 비공개 Storage 버킷에 저장한다. 공개 버킷 및 공개 URL은 금지한다.
- GitHub 저장소에는 비밀키, 실제 발급 PDF, 실제 검사자료를 저장하지 않는다.

## 목표 아키텍처
1. GitHub Pages: 처방전 작성 UI 및 발급대장 UI
2. Supabase Auth: 사용자 인증
3. Supabase Edge Functions: 발급, 재발급, 취소, 파일 열람 권한 검증
4. PostgreSQL: 발급대장, 파일 메타데이터, 감사 이력, 사용자 프로필
5. Supabase Storage: 비공개 PDF 원본 보관

기관의 외부 클라우드·개인정보·기록물 보안 승인 전에는 실제 검사자료를 운영 환경에 입력하지 않는다. 기관 정책상 외부 SaaS가 불허되면 승인된 내부 서버로 이전한다.

## 역할
- inspector: 발급, 지사 발급대장 조회, 권한이 있는 PDF 열람/다운로드, 취소 요청
- branch_admin: 위 기능 + 사용자 활성화/비활성화, 취소/재발급 승인, 지사 감사 이력 조회
- disabled profile: 모든 업무 접근 거부

기본 정책은 같은 지사 내 활성 사용자에게 지사 발급대장 조회 권한을 주는 것이다. 필요하면 별도 승인으로 본인 발급 건만 조회하는 정책으로 좁힐 수 있다.

## 발급 처리 상태
- pending: 발급 작업 시작
- completed: PDF 업로드 및 발급대장 기록 완료
- failed: 발급 처리 실패, 사용자에게 완료로 표시하지 않음
- cancelled: 관리자 승인으로 취소됨
재발급은 기존 레코드를 덮어쓰지 않고 새 발급번호와 기존 건 참조를 생성한다.

## 발급번호
ESP-YYYYMMDD-NNNN 형식. 서버에서 지사별 일련번호를 트랜잭션으로 발급하고 DB UNIQUE 제약조건으로 중복을 차단한다. 브라우저에서 발급번호를 결정하지 않는다.

## PDF 보안
- Storage bucket은 private
- 브라우저에 service-role 키를 절대 전달하지 않는다.
- PDF 열람/다운로드는 Edge Function이 JWT, 활성 프로필, 지사, 발급 상태를 검증한 뒤 처리한다.
- 가능하면 서버 프록시 스트리밍을 사용한다. 서명 URL을 쓸 경우 짧은 만료시간을 적용하고 URL을 로그에 남기지 않는다.
- DB RLS와 Storage 정책은 방어 계층으로 적용한다.
- 실제 발급 완료 응답은 파일 저장과 DB 상태 전환이 성공한 뒤에만 반환한다.

## 데이터 모델
- profiles: auth 사용자, 지사, 역할, 활성 상태
- prescriptions: 발급번호, 처방전 스냅샷, 평가점수, 발급자, 발급일, 상태, 재발급 관계
- prescription_files: Storage 경로, SHA-256, 크기, MIME, 생성 시각
- prescription_events: 발급/열람/다운로드/취소/재발급/권한변경 이력
- issuance_counters: 지사·발급일별 발급번호 카운터(서버 전용)

## 구현 단계
1. 기관 보안·클라우드 사용 승인 및 담당자 지정
2. Supabase 프로젝트 생성, Auth 설정, SQL migration 적용
3. 관리자 프로필과 지사 사용자 계정 등록 절차 구성
4. Edge Functions: issue-prescription, get-prescription-pdf, cancel-prescription, reissue-prescription
5. 기존 작성 UI에 로그인, 발급 API, 발급 결과 연결
6. 발급대장 검색·상세·PDF 다운로드 UI
7. 보안/장애 테스트 후 소수 사용자 시범 운영

## 완료 조건
- 비로그인 사용자는 발급대장 및 PDF에 접근 불가
- 다른 지사 및 비활성 사용자는 데이터·파일에 접근 불가
- 클라이언트가 발급번호, 발급자, 상태를 임의로 지정할 수 없음
- 동일 요청 재전송으로 중복 발급되지 않음
- PDF 저장 실패 시 완료 처리되지 않고 재시도/실패 이력이 남음
- 취소·재발급이 기존 PDF나 발급 이력을 덮어쓰지 않음
- 서비스 키 및 실제 PDF가 GitHub 저장소/브라우저 번들에 없음
