# 승강기 안전처방전 자동 보관·발급대장 구축 명세

## 확정 운영 조건
- 사용자 범위: 지사에서 등록한 검사원 및 관리자
- 로그인: 사용자의 GitHub 계정으로 로그인
- 접근 권한: 최초 로그인 후 관리자가 등록/활성화한 사용자만 발급대장과 PDF를 조회
- 같은 지사의 활성 사용자는 발급 내역 전체를 조회하고 PDF를 열람·다운로드할 수 있다.
- 기존 GitHub Pages 작성 화면은 유지하되, 발급 완료 및 보관 처리는 백엔드에서 수행
- PDF는 비공개 Storage 버킷에 저장한다. 공개 버킷 및 공개 URL은 사용하지 않는다.
- GitHub 저장소에는 비밀키, 실제 발급 PDF, 실제 검사자료를 저장하지 않는다.

## 목표 아키텍처
1. GitHub Pages: 처방전 작성 UI, 로그인 화면, 발급대장 UI
2. Supabase Auth: GitHub OAuth 로그인
3. Supabase Edge Functions: 발급 및 PDF 열람/다운로드 권한 확인
4. PostgreSQL: 발급대장, 파일 메타데이터, 사용자 프로필
5. Supabase Storage: 비공개 PDF 원본 보관

이 버전에서는 복잡한 승인·감사 절차를 최소화한다. 다만 실제 검사자료를 외부 클라우드에 저장해도 되는지는 기관 내부 규정을 확인한다. 승인 전에는 테스트 자료만 사용한다.

## 접근 권한
- 사용자는 GitHub 계정으로 로그인한다.
- 관리자는 해당 사용자의 프로필을 활성화하고 지사 및 역할을 지정한다.
- 같은 지사에 속한 활성 사용자는 발급대장 전체 조회와 PDF 열람/다운로드가 가능하다.
- 비활성 사용자 및 등록되지 않은 사용자는 업무 데이터에 접근할 수 없다.
- 사용자가 직접 자신의 지사나 관리자 권한을 변경할 수 없도록 한다.

## 발급 처리 상태
- pending: 발급 작업 시작
- completed: PDF 업로드 및 발급대장 기록 완료
- failed: 발급 처리 실패, 사용자에게 완료로 표시하지 않음
- cancelled: 발급 취소 표시
재발급은 기존 레코드를 덮어쓰지 않고 새 발급번호로 별도 기록한다.

## 발급번호
ESP-YYYYMMDD-NNNN 형식. 서버에서 발급번호를 할당하고 DB UNIQUE 제약조건으로 중복을 차단한다. 브라우저에서 발급번호를 결정하지 않는다.

## PDF 보관
- Storage bucket은 private
- 브라우저에 service-role 키를 절대 전달하지 않는다.
- PDF 열람/다운로드는 Edge Function이 로그인 상태와 활성 프로필을 확인한 뒤 처리한다.
- PDF 저장과 발급대장 기록이 성공한 뒤에만 발급 완료로 표시한다.

## 데이터 모델
- profiles: Auth 사용자, 지사, 역할, 활성 상태
- prescriptions: 발급번호, 처방전 스냅샷, 평가점수, 발급자, 발급일, 상태
- prescription_files: Storage 경로, SHA-256, 크기, MIME, 생성 시각
- prescription_events: 발급/취소/재발급 관련 기본 이력
- issuance_counters: 발급번호 카운터(서버 전용)

## 구현 단계
1. Supabase 프로젝트 생성
2. GitHub OAuth 로그인 공급자 설정
3. SQL migration 적용 및 private Storage 버킷 생성
4. 관리자가 검사원 프로필을 활성화하는 간단한 등록 절차 구성
5. Edge Functions 배포
6. 기존 작성 UI에 로그인, 발급 API, 발급대장 조회·상세·PDF 다운로드 연결
7. 테스트 계정과 가상 PDF로 동작 확인

## 완료 조건
- 로그인하지 않은 사용자는 발급대장 및 PDF에 접근할 수 없음
- 등록되지 않거나 비활성화된 사용자는 업무 데이터에 접근할 수 없음
- 같은 지사의 활성 사용자는 발급 내역 조회 및 PDF 열람/다운로드 가능
- 서비스 키와 실제 PDF가 GitHub 저장소/브라우저 코드에 포함되지 않음
